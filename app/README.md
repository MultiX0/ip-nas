# Nur app

Nur (نور, "light") is the app I use to talk to my NAS. You chat with AI models, either the small local models that
run on the Raspberry Pi through Nur Hub or cloud models with your own API key, and you can call Nur and talk, in
Arabic or English, with Fish Audio Drama 3 voices. It also shows the NAS status, starts and stops the Docker apps and
downloads models to the Pi.

It is a Flutter app. I build it for Android (7.0 or newer) and Windows (10 or 11, 64-bit), the two I use every day,
and there is a Linux version too (below). The `ios/` folder has the microphone, local network and Bonjour entries, but
I have no Mac, so iOS is untested.

## Build

You need Flutter 3.44 (stable, Dart 3.12) plus the platform tools: Android Studio with the Android SDK for Android,
Visual Studio 2022 with "Desktop development with C++" for Windows. `flutter doctor` shows what is missing.

```bash
cd app
flutter pub get
flutter run            # pick the phone, Windows or Linux
flutter test
```

Release builds:

```bash
flutter build apk --release --split-per-abi
flutter build windows --release
```

The APK is signed with the debug key (see `android/app/build.gradle.kts`), so add your own signing config before you
publish it anywhere. The Windows app ends up in `build/windows/x64/runner/Release/`: `nur.exe` with its DLLs and the
`data` folder, copy the whole folder. If the Windows build stops with path-too-long errors, clone the repo to a short
path such as `C:\src`.

The database code in `lib/data/db/app_db.g.dart` is generated by drift. After changing the tables, run
`dart run build_runner build --delete-conflicting-outputs`.

## Linux

The [Releases](https://github.com/MultiX0/ip-nas/releases) page has `nur-linux-x64.tar.gz`. It is built on Ubuntu
24.04 and runs there or on anything newer. Unpack it into its own folder and start `nur`:

```bash
sudo apt install libgtk-3-0 libsecret-1-0 gnome-keyring pulseaudio-utils xdg-desktop-portal-gtk
mkdir nur && tar -xzf nur-linux-x64.tar.gz -C nur
./nur/nur
```

A normal Ubuntu desktop has all of these already. The API keys go into the desktop keyring (GNOME Keyring on
Ubuntu), the microphone is recorded with `parecord`, which works with PulseAudio and PipeWire, and file dialogs open
through the desktop portal. The app keeps its database and files in `~/.local/share/app.nur.nur`. I don't use Linux
every day, so this version gets less testing than the other two.

To build it yourself (Ubuntu or Debian):

```bash
sudo apt install clang cmake git ninja-build pkg-config libgtk-3-dev liblzma-dev libstdc++-12-dev libsecret-1-dev
cd app
flutter build linux --release
```

The app ends up in `build/linux/x64/release/bundle/` (`nur`, `lib` and `data`); copy the whole folder.

## Pair it with Nur Hub

Install Nur Hub on the NAS first ([hub/README.md](../hub/README.md)). Then put the phone or PC on the same network
as the NAS, open Nur and tap **Connect my NAS** (on the welcome screen, or on the NAS page later). Nur looks for hubs
with mDNS (`_nurhub._tcp`); when that finds nothing it tries port 8770 on every address of your local network. Tap
your NAS and you are done.

There is no pairing code. The first device that pairs becomes the owner right away. When another phone asks later,
every paired Nur app shows "New device wants to connect", and that phone gets its token once you tap Approve.

If the search finds nothing (mDNS blocked, or the NAS is on another subnet), tap **Enter the address manually** and
type the NAS address, for example `192.168.1.50`. The port is 8770 unless you type another one.

After pairing, Nur makes the best model that is already on the NAS the default, and the NAS shows up in the model
picker next to the cloud providers. With no model on the NAS yet, open NAS, Models, Get models. To pair with a
different NAS, or to start over, use the menu at the top right of the NAS page.

## API keys

Nothing is built in. Every key is pasted into the app and kept in the system's secure storage on that device (through
flutter_secure_storage), not in the database and not in this repo.

- Fish Audio, for the voice: Settings, Voice, "Fish Audio API key", or paste it when the first call asks for it.
  Keys come from [fish.audio/app/api-keys](https://fish.audio/app/api-keys). What the app sends to Fish and the
  timings I measured are in [docs/FISH_AUDIO.md](../docs/FISH_AUDIO.md).
- Cloud models: Settings, Models & providers. There are presets for OpenAI, Anthropic, Google Gemini, OpenRouter,
  Groq, DeepSeek, Mistral, xAI and Together, each with a link to its key page. LM Studio, vLLM, llama.cpp and
  any other OpenAI-compatible server work too, with or without a key.
- The NAS needs no key. Pairing gives the app a token for the hub, and the hub forwards model requests to llama.cpp
  on the Pi.

## Screens

The voice call, the NAS page and the pairing are the ones in the video.

- **Chat** (`/`): streaming replies with Markdown, code and images, a model picker, thinking levels, voice messages,
  read-aloud, and a ring that shows how full the context window is. Tools run from the chat (NAS status, Docker,
  web search through SearXNG, commands, memory, MCP servers and skills) and the risky ones ask first.
- **Voice call** (`/call`): the sky orb, live captions, mute and the voice picker. Talk over Nur to interrupt it, or
  tap the orb. On a PC with loud speakers and no echo cancellation the app can't always tell your voice from its own,
  so use headphones or tap. On a phone the mic goes off while the app is in the background and comes back with it.
- **NAS** (`/nas`): Overview (CPU, memory, temperature, uptime, network, disks), Apps (the Docker containers, with
  start, stop, restart, logs and remove), Models (installed ones, the hub's list for a 4 GB Pi, Hugging Face search,
  downloads) and Runtimes (install, start or stop llama.cpp).
- **Setup** (`/setup`): shown instead of the chat until the NAS is paired and answering, llama.cpp is installed and
  running on it, and at least one model is downloaded (only the models that fit the NAS's RAM are listed).
- **Disclaimer** (`/disclaimer`): linked from the line under the chat box; the same text as `DISCLAIMER.md`.
- **Pairing** (`/onboarding`): the search for hubs and the approval wait described above.
- **Settings** (`/settings`): models and providers, memory, tools, MCP and skills, voice, theme and language.

On a wide window (desktop) the chats live in a sidebar and the settings open as a dialog. Shortcuts: Ctrl+N new chat,
Ctrl+K search, Ctrl+Shift+S sidebar, Ctrl+, settings.

How the code is organised is in [ARCHITECTURE.md](ARCHITECTURE.md).
